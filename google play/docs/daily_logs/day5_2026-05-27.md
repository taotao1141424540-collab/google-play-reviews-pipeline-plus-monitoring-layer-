### 2) Priority model implementation

Base formula (design doc):

```text
Priority Score = Frequency × Impact × Severity
```

Operationalized as:

- Frequency = `theme_share`
- Impact = `max(rating_gap, 0)` for negative themes; positive themes set to 0
- Severity = `share_low_1_2`
- Critical Theme Flag (`crash_bug`, `account_login`, `purchase_issue`) gets uplift:
  `score *= 1.5`

Normalization:
- `frequency_norm`, `impact_norm`, `severity_norm` via Min-Max scaling (0-1)
- Final global score:
  `priority_score = frequency_norm × impact_norm × severity_norm × 1.5^is_critical`

Bucket logic:
- P0/P1/P2/P3 by negative-theme score quantiles (Q3/Q2/Q1 split)
- Critical themes can be promoted to P0 when score > 0
- Positive themes are kept in output but mapped to P3 (preserve signals, not fix backlog)
